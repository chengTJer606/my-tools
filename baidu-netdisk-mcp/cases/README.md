# 网盘重复文件分析 · 案例方法论

> 两次实战（全盘排重、指定目录整理）提炼的通用方法。个人场景数据已剔除，仅保留可复用的脚本与经验。

## 适用场景

- **场景一：全盘重复分析**——扫描全部（或排除指定）顶层目录，找出跨目录重复文件
- **场景二：指定目录整理**——针对某个目录树的子目录做去重与聚合整理

## 工作流

```
scan_example.py（扫描出清单 JSON）
    → analyze.py（重复判定分组）
    → 人工核对 dup_groups.json
    → MCP file_move 聚合到 _待删除_<日期>/ 目录
    → 网盘网页端手动删除该目录
```

> 为什么删除要手动：MCP 工具集没有删除接口，REST 直调删除返回 31296（个人体验 token 限制），聚合 + 手动删是目前最稳的路径。

## 判定逻辑（analyze.py）

| 类型 | 规则 | 置信度 | 处置建议 |
|------|------|--------|---------|
| NAME_SIZE_DUP | 同名 + 同 size | 强（可安全删副本） | 保留 1 份，其余移入待删除区 |
| SIZE_HINT_DUP | 仅同 size（不同名） | 弱（可能是同文件） | 人工确认后处置 |

弱判定过滤条件（防误报）：size > 100 KB 才纳入；同一 size 全树出现次数 < 200（排除"每张照片都差不多大"的常见尺寸）。

## MCP 行为踩坑记录

### file_list 分页陷阱
- **不带 `page` 参数只返回 10 条**，不是全量。必须手动分页（page=1, 2, 3... 直到返回空）
- 每页固定 10 条，按 `server_mtime` 倒序

### file_move 速率限制与绕过
- **async=0（同步）**：极易触发 errno=12 "系统繁忙"，即使串行单条调用也很快限流
- **async=2（异步）**：可绕过速率限制，始终返回 errno=0 + taskid，不阻塞
- 单次 `filelist` 最多传约 100 条（实测安全范围 20-50 条）
- 批次间隔 0.5-1 秒即可

### ondup 冲突策略

| 值 | 行为 | 适用场景 |
|----|------|----------|
| `skip` | 目标已存在则跳过 | 恢复操作（避免覆盖已有文件） |
| `newcopy` | 重命名后复制 | 聚合操作（确保不丢文件） |
| `overwrite` | 覆盖 | 明确知道目标可覆盖 |
| `fail` | 直接失败 | 严格模式 |
