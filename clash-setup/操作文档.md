# mihomo (Clash.Meta) 操作文档

## 概述
mihomo 是命令行代理**内核**（后台服务进程，无自带图形界面），已为其配置本地 Web UI 面板，可在**浏览器里图形化操作**，体验近似 Clash 客户端。

本机地址：
- 代理端口：`127.0.0.1:7890`（HTTP 与 SOCKS5 混合）
- 控制 / Web UI：`http://127.0.0.1:9090/ui`
- RESTful API：`http://127.0.0.1:9090`（无密码）

> 当前为**用户级**实例，已配置**开机自启**（`~/.config/autostart/mihomo.desktop` → `autostart-mihomo.sh`），root 旧版已停用并禁用自启。

**系统代理联动规则**（脚本自动完成，无需手动设置）：
- **启动/开机自启**时：先等网络就绪 → 检测节点连通（`generate_204` 探测）→ 通则自动把系统代理设为 `127.0.0.1:7890`；暂不通则后台持续补设约 10 分钟（`ensure-proxy.sh`），连通即自动设上
- **停止**时：自动把系统代理恢复为 `none`（直连），并写入「主动停止」标记
- 360 浏览器等「跟随系统代理」的应用因此无需任何手动设置：代理开着自动走代理，代理关了自动直连
- 若发现代理开着但浏览器直连，终端跑 `bash ~/clash-setup/ensure-proxy.sh` 可立即修复

**自愈看门狗**（`mihomo-watchdog`，systemd --user timer 每分钟触发）：
- mihomo 意外退出（崩溃/被杀）→ 自动拉起
- mihomo 在跑但系统代理缺失 + 节点连通 → 自动补设
- 双击过「停止」（存在 `~/.config/mihomo/.user-stopped` 标记）→ **不会**自动拉起，尊重手动停止；下次「启动」或开机时标记自动清除
- 查看状态：`systemctl --user list-timers mihomo-watchdog.timer`
- 停用/启用：`systemctl --user disable --now mihomo-watchdog.timer` / `enable --now`

**并发保护**：start / stop / autostart / watchdog 共用 `/tmp/mihomo-control.lock` 文件锁串行执行，杜绝并发互杀；启动 mihomo 时已用 `9>&-` 关闭锁描述符，防止锁泄漏。

**设计决策与注意事项**：
- 「主动停止」标记**不跨重启**：开机自启会清除 `.user-stopped`，即重启电脑后代理总是恢复自动运行
- 看门狗会覆盖手动 `gsettings ... mode none`：想临时直连必须双击「停止」（写标记），不能只改系统代理
- 进程存活判定一律用 `pgrep -x mihomo`（进程身份），不用端口监听——9090 可能被其他程序（如 Cockpit）占用
- stop/start 使用 PID 文件前先校验 `/proc/<pid>/comm == mihomo`，防 PID 复用误杀
- mihomo.log 由看门狗自动维护：>10MB 截断保留尾部 1MB
- update-sub 更新前自动备份 config.yaml（`.bak.时间戳`，保留最近 5 个），格式校验失败不会触碰现有配置

## 一、打开 / 关闭代理

### 启动
- 桌面双击 **「mihomo-控制面板」→ 2 启动**
- 或终端：`bash ~/clash-setup/start-mihomo.sh`

### 停止
- 桌面双击 **「mihomo-控制面板」→ 4 停止**
- 或终端：`bash ~/clash-setup/stop-mihomo.sh`

> 快捷方式机制（2026-11-09 修复）：5 个 .desktop 的 Exec 已全部改为**无引号的最简形式**（旧 `bash -c '...'` 写法违反 desktop entry 规范，含保留字符，严格解析器会拒绝执行导致双击无反应）。启动/停止/更新订阅经 `run-in-terminal.sh` 包装器执行——无论脚本成败，终端窗口都会暂停显示结果，报错不再一闪而过。

### 查看是否在运行
终端：`ss -tln | grep 7890` —— 有输出=运行中；无输出=已停止。
或：`ps -ef | grep mihomo | grep -v grep`

## 二、切换节点（Web UI 图形操作）

1. 浏览器打开 `http://127.0.0.1:9090/ui`（或控制面板 → 7）
2. 首次进入若要求填「后端地址」，输入：`http://127.0.0.1:9090`，密码留空，点添加
3. 进入 **「代理」** 页：
   - 点 **「节点选择」** 组 → 在列表里选一个节点（如「日本-优化」「香港-优化」）
   - **「自动选择」** 组会自动测速并选延迟最低的节点
4. 顶部可切换**运行模式**：
   - `规则(rule)` 按分流规则走（默认，推荐）
   - `全局(global)` 所有流量走所选节点
   - `直连(direct)` 所有流量直连（等于关代理）
5. **「连接」** 页可看当前活跃连接；**「日志」** 页看实时日志

## 三、重启电脑后怎么操作

mihomo **已配置开机自启**。重启电脑后**无需任何操作**：

1. `autostart-mihomo.sh` 自动运行：等网络就绪 → 启动 mihomo → 检测节点 → 通即设系统代理
2. 若开机时网络慢导致首轮检测失败，后台会自动补设（约 10 分钟内连通即生效）
3. 想换节点：控制面板 → 7 打开 Web 面板里选

> 若开机后浏览器上不了外网（极小概率补设也未成功），终端跑 `bash ~/clash-setup/ensure-proxy.sh` 立即修复。

## 四、系统 / 浏览器代理设置

把代理设为 **`127.0.0.1:7890`**（HTTP 与 SOCKS5 都填这个）：
- 系统设置 → 网络 → 网络代理 → 手动
- 浏览器（Edge）：设置 → 系统 → 打开计算机代理设置，或装 SwitchyOmega 扩展指定 `127.0.0.1:7890`

## 五、更新订阅（节点变化时）

控制面板 → 5 更新订阅**（原旧快捷方式已归档至 removed-shortcuts/）**（或终端 `bash ~/clash-setup/update-sub.sh`）：
脚本会自动拉取最新机场配置、补本地设置（geodata-mode / external-controller / external-ui）、重启 mihomo。

> 手动更新命令见 `~/clash-setup/update-sub.sh` 脚本内容。

## 六、可选：桌面 GUI 客户端（更「软件化」）

若想要系统托盘式的独立客户端（比浏览器面板更像「软件」），可下载 MetaCubeXD 的 arm64 AppImage：

```bash
aria2c -x16 -s16 -d ~/clash-setup -o MetaCubeXD.AppImage \
  "https://ghproxy.net/https://github.com/MetaCubeX/metacubexd/releases/download/v1.273.0/MetaCubeXD-1.273.0-linux-arm64.AppImage"
chmod +x ~/clash-setup/MetaCubeXD.AppImage
~/clash-setup/MetaCubeXD.AppImage   # 双击或运行，启动后连接 http://127.0.0.1:9090
```

AppImage 约 145MB，免安装直接运行，提供托盘图标、图形选节点、连接管理。

## 七、恢复 root 旧版

若想切回系统原来的 root 级 mihomo（systemd 托管）：
```bash
sudo systemctl enable --now mihomo.service
```
（会重新占用 7890/9090，需先停掉用户级：`bash ~/clash-setup/stop-mihomo.sh`）

## 常见问题

**Q: 双击桌面快捷方式没反应？**
麒麟可能要求「允许执行」。右键快捷方式 → 属性 → 权限 → 勾选「允许作为程序执行」。或终端 `chmod +x ~/桌面/mihomo-*.desktop`。

**Q: 面板打开是空白？**
确认 mihomo 已启动（`ss -tln | grep 9090`），再刷新 `http://127.0.0.1:9090/ui`。

**Q: 代理开了但上不了网？**
面板「代理」页检查「节点选择」是否选了可用节点；模式是否为「规则」；可切到「自动选择」让它选最快节点。

**Q: 启动报端口占用？**
可能有另一个 mihomo 在跑。先 `bash ~/clash-setup/stop-mihomo.sh`，再启动。

**Q: mihomo 在运行，但浏览器打不开谷歌？**
多半是系统代理没设上（历史曾发生在开机网络未就绪时）。终端跑 `bash ~/clash-setup/ensure-proxy.sh` 自动检测并补设；或检查 `gsettings get org.gnome.system.proxy mode` 应为 `'manual'`。
