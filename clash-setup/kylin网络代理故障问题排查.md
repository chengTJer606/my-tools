### 1.2 根因：三层叠加

**迁移动 git 本身没有问题，不是故障根源。** 真正的根因是：

1. **系统 DNS 间歇性瘫痪**（手机热点 DNS 转发不稳 + DNSSEC 校验误杀）——"时好时坏、重启就好、过会又坏"的总根源；
2. **mihomo 节点域名解析被 `nameserver-policy: system://` 绑死在系统 DNS 上**——系统 DNS 一挂，代理跟着全灭，形成"直连代理同时断"的全断局面；
3. **脚本健康检查探测 gstatic.com，命中 `GEOIP,CN,DIRECT` 实际走直连**——节点全挂时检查照样"通过"（假阳性），掩盖了前两个问题。

**完整因果链：**

```
手机热点(192.168.43.1) DNS 转发不稳 / DNSSEC missing-key 误杀
        ↓
systemd-resolved 对所有域名间歇返回 SERVFAIL
        ↓
① 直连应用全挂（浏览器直连、湛卢 zl serve → moma.cmecloud.cn 解析失败）
② mihomo 节点域名被强制走 system:// → 同样 SERVFAIL → 代理也连不上
        ↓
健康检查走 gstatic → GEOIP,CN,DIRECT → 直连碰巧时通时断
→ 脚本/看门狗误判"节点正常"，不设防也不报警
        ↓
表现为：全网时好时坏、湛卢 Cannot connect to API、重启碰运气
```

## 五、360 浏览器专项（代理的主使用场景）

### 5.1 原理

360（Chromium 内核 126）Preferences 中 `proxy.mode = "system"`，**实时监听 GNOME gsettings，切换不需要重启浏览器**。所以治理思路不是"改 360"，而是**把 gsettings 与 mihomo 真实状态焊死**：mihomo 活 → manual；死 → none。历史故障的本质全是"gsettings 与现实不一致"，不是浏览器迟钝。

### 5.2 实测（CDP 驱动全程不重启的 360 实例）

| 阶段 | 系统代理 | 360 出口 IP | 说明 |
|---|---|---|---|
| A 运行中 | manual | 45.149.92.22 | 节点出口，确实走代理 |
| B 双击停止 | none | 直连（百度 200、海外站失败） | **实时切直连，未重启浏览器** |
| C 双击启动 | manual | 45.149.92.22 | 实时切回代理 |

另经 headless 360 内核实测：github 完整加载 526KB；出口 IP 与 curl 代理出口一致。

### 5.3 历史"代理开着浏览器不走"四个成因的最终状态

| # | 历史成因 | 状态 |
|---|---|---|
| 1 | 健康检查假阳性（gstatic 走 DIRECT） | ✅ 已修 |
| 2 | ensure-proxy 与 stop 竞态写回 manual | ✅ 已修（双重停止标记检查） |
| 3 | 系统 DNS 挂 → 节点域名解析失败 | ✅ 已架构解耦（独立 DoH） |
| 4 | 浏览器先启动、代理后设置的理论窗口 | ⚠️ Chromium 监听 gsettings 1~2 秒内生效；极偶发时重启浏览器即可 |

### 5.4 浏览器侧使用注意

1. 360 设置保持**「使用系统代理」**，别手动改；不要叠加 SwitchyOmega 等代理插件。
2. QUIC/HTTP3 个别网站首次打开慢可在 `chrome://flags` 禁用 QUIC。
3. ignore-hosts 已含 172.16.0.0/12；访问公司内网 172.x 服务若打不开再说。
4. 最快验证是否走代理：浏览器开 `https://api.ipify.org`，非运营商 IP 即走了代理。

## 六、换网络全自动适配（2026-11-10 部署）

**换任何公网 WiFi/热点/网线，什么都不用手动改。**

- 钩子：`/etc/NetworkManager/dispatcher.d/90-mihomo-dns-autofix`（源码 `nm-dns-autofix.sh`，root 755）
- 行为：任何 WiFi/有线 `up|dhcp4-change|reapply` 事件 → 自动把该连接 DNS 固定为 `223.5.5.5/119.29.29.29` 并立即生效，写日志到 `~/clash-setup/network-events.log`；已固定过的只记状态不重复操作；VPN/网桥/容器接口跳过。
- 实测：故意取消 DNS 固定 → 3 秒内自动恢复并写日志；重复触发不重复操作；网络零扰动。
- 各组件换网行为：mihomo 不受影响（只听 127.0.0.1）；系统代理不受影响（桌面级设置）；DNS 自动适配；湛卢直连恢复 + FallbackDNS 兜底。
- 唯一例外：企业内网必须用内网 DNS 时，把该连接 `ipv4.ignore-auto-dns` 改回 `no`，或把连接名写进钩子 `EXCLUDE` 变量。

## 十三、30 秒自查

```bash
# 代理通道（通=代理OK）
curl -s -x http://127.0.0.1:7890 -o /dev/null -w "%{http_code}\n" --max-time 8 https://www.google.com/generate_204
# 直连通道（通=系统DNS/直连OK）
curl -s -o /dev/null -w "%{http_code}\n" --max-time 6 https://www.baidu.com
```

- **都挂** → `resolvectl query www.baidu.com` 看 SERVFAIL；系统 DNS 问题（换网后钩子一般 3s 内自动修）。
- **代理挂、直连通** → 面板停止再启动；看门狗 30s 内也会自动修。
- **代理通、直连挂（湛卢报错）** → 系统 DNS 问题，代理无恙。
- 想看日志：`tail -50 ~/clash-setup/mihomo.log`；手动补代理：`bash ~/clash-setup/ensure-proxy.sh`。
